5. DEFECTS IDENTIFIED, ROOT CAUSES & CONCRETE FIXES
--------------------------------------------------------------------------------
1. DEFECT: Three.js Version Mismatch Causing GLTFLoader Failure
   - Severity: CRITICAL / BLOCKER
   - Evidence: Console error "Uncaught TypeError: Class constructor ol cannot be invoked without 'new'"
   - Root Cause: assets/lib/three.min.js was an incompatible r128+ build where THREE.Loader
     was defined as an ES6 class. GLTFLoader.js used ES5 `THREE.Loader.call(this, manager)`.
   - Concrete Fix: Replaced assets/lib/three.min.js with the authentic Three.js Revision 123
     build (652,700 bytes) from extracted_ide/microBlock-IDE/dashboard/js/three.min.js.
   - Verification: Three.js r123 loads cleanly without ES6 class constructor errors.

2. DEFECT: Corrupted 3-Byte Header in PT-BOT_Atom_VX.glb
   - Severity: CRITICAL / BLOCKER
   - Evidence: SyntaxError: Unexpected token '\u0003', "\u0003d\u0003glTF\u0002\u0000\u0000"... is not valid JSON
   - Root Cause: assets/models/PT-BOT_Atom_VX.glb had 3 extraneous bytes (0x03 0x64 0x03)
     prepended to the 'glTF' magic header, causing GLTFLoader to mistake it for JSON.
   - Concrete Fix: Restored the authentic binary GLTF file directly from
     assets/extracted_ide/microBlock-IDE/boards/atom-vx/models/PT-BOT_Atom_VX.glb.
   - Verification: Header begins with <Buffer 67 6c 54 46>, model loads in 300 ms.

3. DEFECT: Heading-Lock Angular Wraparound Lerp Inversion
   - Severity: HIGH
   - Evidence: Moving from 179° to -179° lerped across 0° through the 358° long arc.
   - Root Cause: THREE.MathUtils.lerp did not normalize angular difference into [-PI, +PI].
   - Concrete Fix: Implemented shortest-arc normalization:
     while (diff > PI) diff -= 2*PI; while (diff < -PI) diff += 2*PI; robotMesh.rotation.y += diff * 0.08.
   - Verification: test_heading_pd.py verified 13/13 cases; live browser yaw transitions smoothly.

4. DEFECT: 1D Assumption in Line Sensor Cross-Track Distance
   - Severity: HIGH
   - Evidence: Robot reported "OFF LINE" during the first segment of Five-Point Route.
   - Root Cause: Distance was calculated as Math.abs(posZ - pStart.z), assuming all segments
     ran along X. The first segment runs vertically along Z from z=-0.45 to z=+0.15.
   - Concrete Fix: Implemented 2D vector normal projection:
     nx = tz; nz = -tx; crossTrack = (posX - pStart.x)*nx + (posZ - pStart.z)*nz.
   - Verification: test_track_simulation.py passed; live browser HUD reports "ON LINE (0.92)".

5. DEFECT: Bridge Climb/Descent Direction Inversion
   - Severity: MEDIUM
   - Evidence: Robot descended at the start of the bridge and climbed at the end.
   - Root Cause: Five-Point Route traverses bridge from +X (0.35) toward -X (-0.40). Old code
     assumed travel from -X to +X.
   - Concrete Fix: Corrected ramp interval math: climb ramp for X in [0.05, 0.35], deck in
     [-0.15, 0.05], descent ramp in [-0.40, -0.15].
   - Verification: Browser HUD displays pitch +15.0° during climb, 0.0° on deck (+50mm),
     and -15.0° during descent.

6. DEFECT: False T-Junction Detection on Bamboo Speed Bumps
   - Severity: MEDIUM
   - Evidence: Surface status flickered to "JUNCTION" when traversing bamboo rods.
   - Root Cause: Low threshold (>25%) treated bamboo speed bumps (reflectance 0.689 -> 73%)
     as a track junction.
   - Concrete Fix: T-junction requires >= 6 channels reading > 85% calibrated black tape;
     bamboo zones are explicitly tagged as "CROSSING BUMP (Bamboo 0.689)".
   - Verification: test_sensor_array.py confirmed bamboo reflectance produces 73% without
     triggering junction; junctions require >= 6 channels > 85%.

7. DEFECT: Global Object and Function Exporter Desynchronization
   - Severity: MINOR
   - Evidence: Browser test reported null activeProject and switchProject not found.
   - Root Cause: activeProject was defined with lexical scope let without window binding,
     and layout switching was named loadExampleQuickDropBox4Enc.
   - Concrete Fix: Bound activeProject, scene, robotMesh, isSimRunning, and switchProject
     to window in build_rescue_sim_ide.js.
   - Verification: Rebuilt apps/web/index.html, apps/web/tactical_planner.html, and apps/web/web.html.

     connected via USB Serial (e.g., COM3). The local backend API and CLI path are
     verified, but hardware flashing in the browser test is mocked/blocked by absence
     of a physical microcontroller.

     In low-end headless environments without GPU or SwiftShader, hardware acceleration
     must fall back to CPU software rasterization.

   - No original extraction files in assets/extracted_ide were altered.
